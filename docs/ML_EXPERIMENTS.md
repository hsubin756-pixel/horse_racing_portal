# 예측 시점 점검·특성 비교·별도 최종 검증

사용자 특성 비교 결과 검토 후 **제주 combined 후보와 11월 검증 계획**을 정했습니다. 현재 실행 절차는 [검증 묶음 준비](ML_VALIDATION_PLAN.md)를 사용하세요. 아래 단독 freeze/final은 기본 기능 설명이며, 새 묶음 도구가 학습 CSV와 당시 코드까지 함께 보존합니다.

2026-10-28 구현. `ml/experiment.py`는 API를 호출하지 않고 서비스 모델 파일을 만들거나 바꾸지 않습니다. 사용자 PC의 2026 CSV로 실행할 도구이며, 클라우드에서는 가상 테스트 자료와 저장소의 서울 2025 CSV만 직접 확인했습니다.

## 1. 예측 시점 점검 결과

- 기존 `evaluate_extended.build`와 서비스 `real_features`는 같은 날짜/미래의 결과를 **과거 전적 입력**에 포함하지 않습니다. 다만 서비스 모델의 학습 마감일 안에 있는 경주를 다시 계산하면 모델 가중치 자체가 해당 결과를 학습했을 수 있습니다. 과거 경주 화면의 점수는 사전 예측 검증 결과가 아닙니다.
- API155 CSV에는 출주표·마체중·기수 변경·배당의 당시 공개 시각이 없습니다. 과거 경주일을 기준으로 나누더라도 나중에 정정된 자료인지 알 수 없습니다. 정보 이용 가능 시점까지 검증된 실시간 예측이라고 주장할 수 없습니다.
- CSV 변환은 비완주/취소 등을 제외하고 순위가 완전한 경주를 유지합니다. 따라서 평가 대상 말과 `fieldSize`는 사후에 남은 결과 기준입니다. `without_physical`도 평가 모집단의 사후 선택 문제까지 없애지는 못합니다.
- 결과 API의 배당은 **마감 후 사후 비교 기준**으로 취급합니다. CSV에 시각이 없으므로 경주 전 특정 시각의 배당이거나 실제 베팅 가능한 가격이라고 확인한 것이 아닙니다. 기존 문서에서 마감 배당이라고 표현한 것도 이 보수적 취급을 의미합니다.
- 기존 평가의 시장 순위는 동률에도 입력 순서대로 다른 순위를 주며, 동일 예측 점수의 상위 3두 선택도 CSV 행 순서에 영향을 받습니다. 결과 CSV가 착순순이면 평가가 유리해질 수 있습니다. 새 도구는 **마번순으로 정렬하고 배당 동률은 공동 순위**로 계산합니다. 기존 서비스 학습/평가 코드는 바꾸지 않았으므로 과거 수치와 새 수치가 정확히 같을 필요는 없습니다.
- 기수/조교사는 현재 CSV에 ID가 없어 이름을 사용합니다. 새 실험은 경마장별 이름으로 이력을 구분하고 공란끼리는 합치지 않습니다. 경마장 이동 시 이력 단절·같은 경마장의 동명이인 문제는 남습니다. 말은 전국 마번으로 연결합니다.
- 새 도구의 이력은 이전 검증일 결과로 갱신하지만 모델 가중치는 검증 기간에 고정합니다. 현재 서비스는 재학습 전까지 이력도 고정하므로 실험 점수와 서비스 동작은 동일하지 않습니다.

이 점검은 누수를 모두 해결했다는 인증이 아닙니다. 실제 사전 예측 검증에는 출주표/마체중/배당을 정해진 시각에 저장하는 스냅샷, 예측 생성 시각과 입력 해시, 모델 버전, 사후 결과의 별도 연결이 필요합니다. 이번 변경은 오프라인 비교와 최종 기간 고정까지이며 해당 스냅샷 수집은 추가 구현 대상입니다.

## 2. 사용자 PC의 개발용 특성 비교

WSL 저장소에서 실행합니다. 아래 배열은 같은 터미널에서 이어서 사용하세요. 제주 파일은 확대 수집한 CSV로 **교체**합니다. 원래 제주 CSV까지 함께 넣지 않습니다.

```bash
git pull --ff-only origin main
DATA=(
  ml/data/seoul-2025.csv
  .runtime/kra/sync/training/1-20260726-20261025.csv
  .runtime/kra/ml/jeju-expanded.csv
  .runtime/kra/sync/training/3-20260726-20261025.csv
)

.runtime/ml-venv/bin/python ml/experiment.py audit "${DATA[@]}" \
  --output .runtime/kra/input-timing-audit.json

.runtime/ml-venv/bin/python ml/experiment.py compare "${DATA[@]}" \
  --development-end 2026-10-26 --windows 3 --test-days 30 \
  --output .runtime/kra/feature-ablation.json
```

`audit`는 경마장별 기간·경주 수·열별 공란 수·입력 시점 제약을 기록합니다. 같은 경주 내 마번 중복, 날짜/거리 불일치, ID/날짜 불일치는 거부합니다. 제공기관의 스냅샷 시각 또는 정정 이력을 검증하지는 않습니다.

`compare`는 기존에 확인한 7/28~8/27, 8/27~9/26, 9/26~10/26(끝 날짜 제외)을 **개발용 구간**으로 명시합니다. 입력 CSV에 이후 날짜가 추가돼도 `--development-end` 이후 자료는 학습/평가에서 제외하며 검증 구간이 자동 이동하지 않습니다. 동일 경주의 내용이 다른 CSV는 중단하고, 모델 파라미터는 모든 비교에 동일한 고정 RandomForest(120개, 깊이5, 잎 최소8, seed42)를 씁니다.

| 집합 | 입력 |
|---|---|
| base | 과거 평균 착순·출전 수·현재 거리 |
| recent | base + 최근 5회 평균 착순/3위 이내 비율·직전 출전 이후 일수·이력 유무 |
| distance | base + 현재 거리 ±200m 과거 입상 비율·표본 수 |
| connections | base + 기수/조교사의 이전 날짜 입상 비율·표본 수 |
| physical | base + 부담중량·마체중·게이트·남은 결과 두수·나이·성별 |
| combined | 위 입력 모두 |
| without_recent/distance/connections/physical | combined에서 각각 한 묶음 제외 |

모든 집합은 배당·현재 경주의 착순/기록/구간·레이팅을 입력에 넣지 않습니다. 기본값과 소표본 비율의 사전값은 코드에 고정돼 있고 테스트 구간에서 추정하지 않습니다. 이력 없는 말은 `hasHistory=0`, 휴양일수 0으로 구분합니다. 최근/거리 비율은 3회·0.28 사전값으로 완화합니다. 거리 ±200m는 성능 검증 전의 고정 실험 정의입니다.

서울/서울+부산/제주별로 구분하고 통합 모델의 서울·부산 결과는 각각 냅니다. `trainingDaysByTrack/testDaysByTrack`도 기록하므로 통합 학습 날짜가 충분해도 특정 경마장 자료가 적은지 확인할 수 있습니다.

보고서는 전체 대상과 **유효한 배당이 모든 말에 있는 동일 경주 집합**의 지표를 분리합니다. 시장 점수는 공동 배당 순위의 역수로, 확률이 아닙니다. AUC/AP/top3 recall만 비교하고 시장 Brier/정확도는 출력하지 않습니다. Top3 recall은 실제 3위 이내 말 가운데 선택한 3두에 포함된 비율입니다. 동점은 마번순으로 처리합니다.

시장 및 base 대비 top3 recall 차이에는 같은 경주를 짝지은 bootstrap 95% 구간(1,000회)을 기록합니다. 기간 간 의존성·다중 비교를 보정한 유의성 검정이 아닙니다. 최고 점수 한 개만 보고 교체하지 말고 기간별 개선 방향·시장 비교 표본 수·공란과 경마장별 표본을 함께 보세요.

출력 파일은 덮어쓰지 않습니다. 개발 실험을 다시 실행할 경우 새 파일명을 사용하고 무엇을 바꿨는지 기록하세요. 원본 CSV 해시도 보고서에 포함됩니다.

## 3. 별도 최종 검증 기간 고정

개발 결과를 검토해 **후보 하나와 경마장 집합 하나**를 선택한 뒤, 아직 오지 않은 기간을 고정합니다. 다음은 명령 형식 예시이며 `base`를 추천 모델로 선정했다는 뜻은 아닙니다. 후보·기간을 결정하기 전에 무조건 실행하지 마세요.

```bash
.runtime/ml-venv/bin/python ml/experiment.py freeze "${DATA[@]}" \
  --training-end 2026-10-26 \
  --start 2026-11-01 --end 2026-12-01 \
  --cohort jeju --feature-set base \
  --output .runtime/kra/final-plan-jeju.json
```

- 시작일은 실행 당일(한국 시간)보다 미래여야 합니다. 기간이 이미 시작됐으면 **그때도 아직 보지 않은 미래 기간**을 정해야 합니다. 날짜 기준 잠금이며, 사용자가 다른 도구로 결과를 보지 않았는지까지 증명하지 않습니다.
- 학습 마감일·정규화한 학습 행 해시·특성·파라미터·코드 해시·NumPy/scikit-learn 버전을 저장합니다. 기존 계획 파일을 덮어쓰지 않습니다. `seoul`, `seoul_busan`, `jeju` 중 하나입니다.
- 서비스에는 적용하지 않으며, 최종 기간 결과를 보면서 후보/기준을 바꾸면 더 이상 그 기간은 최종 검증이 아닙니다. 학습 자료나 실험 코드가 바뀌어도 기존 계획으로 평가하지 않습니다.
- 학습 마감일과 검증 시작일 사이의 결과는 모델 학습에 넣지 않습니다. 고정된 규칙에 따라 각 예측일 이전의 **이력 입력 갱신에만** 사용할 수 있습니다. 검증 기간 중에도 이전 날짜 이력만 갱신합니다.
- 최소 학습 날짜 20일, 검증 날짜 5일입니다. 모든 개최일 수집 완료를 CSV만으로 증명하지 못하므로 수집 진행표의 완료 여부도 별도 확인합니다.

예시 기간이 끝난 **2026-12-01 이후**, 기간 자료 수집을 마치고 기존 학습 CSV와 신규 CSV를 함께 전달합니다. 아래 `new-jeju-results.csv`는 실제 수집해 내보낸 파일 경로로 바꾸세요.

```bash
.runtime/ml-venv/bin/python ml/experiment.py final "${DATA[@]}" \
  .runtime/kra/ml/new-jeju-results.csv \
  --plan .runtime/kra/final-plan-jeju.json \
  --output .runtime/kra/final-evaluation-jeju.json
```

기간 종료 전 실행, 변경/누락된 학습 행, 달라진 코드/수치 라이브러리, 최소 날짜 미달을 거부합니다. 최종 결과 파일도 덮어쓰지 않습니다. 계획 및 결과를 백업하고, 이후 자료 정정으로 다시 실행해야 한다면 사유와 기존 결과를 보존하세요. 서비스 모델 교체는 자동 실행하지 않습니다. 이 최종 검증도 결과 CSV의 시점 한계가 있는 **시간순 사후 검증**이며 실제 경주 전 공개 시각 검증을 대신하지 않습니다.

## 직접 확인한 범위

- 사용자 보고: 제주 60개 유효 경주일·444경주·4,183건. 확대 자료로 세 구간 AUC 0.676/0.685/0.665, 시장 0.739/0.753/0.737. 세 구간 모두 기존 실험 모델이 시장보다 낮음. 클라우드에 해당 CSV는 없음.
- 클라우드 서울 2025: 97일·1,018경주·10,555건. 마체중 공란 658건. 새 비교의 base AUC 0.674/0.712/0.709, combined 0.716/0.753/0.735, 시장 0.790/0.822/0.767. 모든 집합이 세 구간 모두 시장보다 낮음. 일반화된 개선/교체 결론은 아님.
- 사용자 2026 확대 CSV의 새 특성 비교와 미래 최종 검증은 아직 실행하지 않았습니다. 최종 기간은 후보 선택 후 사용자 PC에서 고정해야 합니다.
