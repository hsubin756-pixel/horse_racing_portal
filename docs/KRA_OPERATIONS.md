# 데이터 운영 후속 작업 — 2026-10-28

백업 완료 후 적용하는 다섯 단계입니다. 실제 API 인증키와 기존 수집 자료는 사용자 WSL에 있으므로 클라우드 테스트 결과와 사용자 실제 실행 결과를 구분합니다.

## 1. 업데이트와 경주불성립 반영

V12 마이그레이션과 관리자 화면을 포함합니다. 기존 백업을 보관하고 아래를 실행하세요.

```bash
git pull --ff-only origin main
./scripts/up.sh
python3 scripts/kra_sync.py --from 20260726 --to 20261025 --max-calls 0 --apply --retry-failed
python3 scripts/kra_sync.py --from 20260726 --to 20261025 --status
```

재처리는 API를 호출하지 않습니다. 모든 출주마가 `98/경주불성립`이고 결승 시간이 공란/0인 경우 별도 `VOID` 상태로 반영합니다. 출주표·원본은 보존하지만 착순·결승 시간·배당·구간을 만들어 넣지 않습니다. 일반 완료와 불성립 결과가 섞여 있거나 양수 결승 시간이 있으면 보류합니다. 말·기수 등의 다른 필수 검증도 유지합니다.

화면에 경주불성립 안내를 표시하고 예측 링크를 숨깁니다. API도 예측을 거부하며 완주 전적·성적 통계에 포함하지 않습니다. 출전취소나 일반 완료로 대체하지 않습니다. 사용자 실제 불성립 1경주의 처리 성공 여부는 위 명령 결과로 확인해야 합니다.

## 2. 미제공 자료만 재조회하고 비교

기존 `--retry-failed`는 캐시만 다시 검사합니다. 제공기관 응답 자체가 정정됐는지 확인하려면 별도 재조회 도구를 사용합니다.

```bash
# 대상 경주 목록만 확인: API 호출·DB 변경 없음
python3 scripts/kra_recheck.py plan .runtime/kra/sync/20260726-20261025-123.json

# 보류 경주만 최대 5회 요청. 기존 원본 보존, DB 변경 없음
python3 scripts/kra_recheck.py fetch .runtime/kra/sync/20260726-20261025-123.json --max-calls 5 --report .runtime/kra/rechecks/review-20261028.json
```

같은 `fetch` 명령/보고서 경로로 재개하면 이미 비교한 경주는 건너뛰고 다음 보류 경주를 조회합니다. 페이지 캐시도 재사용합니다. 호출 한도는 실행당 실제 요청 횟수이며 원래 기간 작업의 누적 호출 수에도 더합니다. 제공기관의 일일 사용량을 조회하는 기능은 아니므로 계정 한도에 맞춰 실행하세요. 네트워크 오류는 중단하고 원인을 확인합니다.

터미널과 보고서에는 이전/신규 행 수·변경 필드명·검증 결과를 기록합니다. 원본의 값 전체나 인증키는 출력하지 않으며 보고서의 원본 경로를 통해 로컬에서 상세 비교할 수 있습니다. `검증 통과` 자료를 확인한 뒤 다음 명령으로 반영합니다.

```bash
python3 scripts/kra_recheck.py apply .runtime/kra/rechecks/review-20261028.json
python3 scripts/kra_sync.py --from 20260726 --to 20261025 --status
```

이 단계도 API 호출은 없습니다. 비교 이후 원본 해시·보류 상태가 바뀌면 중단합니다. 아직 DB에 반영되지 않은 검증 통과 경주만 반영하며, 이미 반영된 경주의 변경 결과를 덮어쓰는 정정 기능은 아닙니다. 기존 원본과 새 원본을 모두 보존합니다. 한 경주씩 트랜잭션으로 반영하고 진행 기록을 저장하므로 도중 실패 시 앞서 성공한 경주는 유지됩니다. 같은 보고서 재실행은 중복 반영하지 않습니다.

신규 응답도 착순 0/거리 공란이면 계속 보류합니다. 모든 자료를 받아도 보완을 보장하지 않습니다. 이후 다른 날짜에 다시 확인할 때는 **새 보고서 파일명**을 사용하세요. 완료된 보고서를 같은 이름으로 실행하는 것은 새 조회가 아닙니다.

## 3. 관리자 데이터 상태 화면

로그인 후 **자료 관리 → 한국마사회 데이터 상태**에서 확인합니다. 일반 회원은 볼 수 없습니다. 관리자 지정은 기존 계정에 대해 `python3 scripts/admin.py 본인계정이메일`로 수행합니다.

- DB의 실제 KRA 경주 수·불성립 수·자료 기간·마지막 반영 시각
- 기간별 날짜×경마장 작업 수·사이트 완료·학습 수집 완료·반영 경주/보류 경주 수
- 마지막 작업 시각·누적 호출·보류 사유와 새로고침

진행표는 마지막 작업 시점의 기록이며 실시간 API 상태가 아닙니다. 서로 겹치는 기간의 작업을 합산하지 않습니다. 최대 최근 파일명 순 100개 작업을 표시하고 읽지 못한 파일은 별도 안내합니다.

원본과 인증키를 웹 컨테이너에 연결하지 않습니다. `sync.save`가 경로·원본을 제외한 화면용 JSON을 `sync/dashboard`에 발행하고 이 디렉터리만 읽기 전용으로 연결합니다. `up.sh`도 기존 진행 기록을 처음 발행합니다. 필요한 경우 다음 명령으로 다시 발행할 수 있습니다(API 호출 없음).

```bash
python3 scripts/kra_status.py
```

화면용 스냅샷은 로컬에서 읽을 수 있는 0644 권한이며, 실제 원본과 진행 파일의 비공개 권한은 유지합니다.

## 4. PC에서 정기 갱신

```bash
# 계획만 확인
python3 scripts/kra_daily.py --dry-run
# 최근 7일~어제, 한국 날짜 하루 최대 25회, 검증된 새 자료 반영
python3 scripts/kra_daily.py --max-calls 25 --apply
```

기존 기간 작업을 날짜×경마장 단위로 재사용해 완료 자료를 다시 다운로드하지 않습니다. 같은 한국 날짜에 재실행해도 그날 상한을 공유합니다. 실패한 요청도 소비 횟수에 포함하며 호출 기록이 줄어들면 중단합니다. 상태/호출 기록을 지우면 정상적인 재개를 보장할 수 없습니다. 그날 설정한 기간/상한은 같은 값으로 재개합니다. 수집·재조회·백업과 동시 실행하지 않습니다.

완료/자료 없음 캐시를 자동으로 새로 받거나 보류 정정을 자동 적용하지 않습니다. 늦게 올라온 결과와 정정은 2번 재조회 절차로 확인하세요. 모델 평가/교체도 자동 수행하지 않습니다. 수동 API 호출을 포함한 계정 전체의 제공기관 한도는 별도로 관리해야 합니다.

### Windows 예약 작업 등록

먼저 수동 실행을 확인한 후 **WSL 터미널**에서 등록합니다. 아래 등록은 실제 사용자 Windows에 작업을 추가합니다. 클라우드에서는 등록하지 않았습니다.

```bash
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$(wslpath -w scripts/install-kra-task.ps1)" -Distribution Ubuntu -ProjectPath "$PWD" -At "20:00" -MaxCalls 25
```

매일 Windows 현지 시각 20:00에 현재 사용자 계정의 WSL을 실행합니다. Windows 로그인 상태·PC 전원·Docker Desktop 실행이 필요합니다. 꺼진 PC에서 실행되지 않으며 별도 서버는 필요 없습니다. 작업 이름은 `KEIBA-KRA-Daily`, 중복 실행은 차단하고 최대 실행 시간은 2시간입니다. 실행 기록은 `.runtime/kra/sync/daily-YYYYMMDD.json` 및 Windows 작업 스케줄러에서 확인합니다. 같은 이름의 작업은 무조건 덮어쓰지 않습니다.

등록 제거(WSL):

```bash
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$(wslpath -w scripts/install-kra-task.ps1)" -Remove
```

Windows 스케줄러 실행은 이 Linux 클라우드에서 직접 검증하지 못했습니다. PC에서 첫 예약 실행의 결과를 확인해야 합니다.

## 5. 여러 기간의 모델 재검증

서비스 모델을 바꾸지 않고, 검증 구간 이전 자료로만 학습한 뒤 서로 겹치지 않는 달력 기준 구간을 평가합니다. 이전 검증일의 결과는 그다음 날짜의 과거 이력으로 사용할 수 있지만 같은 날/미래 결과는 입력에 쓰지 않습니다.

```bash
.runtime/ml-venv/bin/python ml/evaluate_windows.py \
  ml/data/seoul-2025.csv \
  .runtime/kra/sync/training/1-20260726-20261025.csv \
  .runtime/kra/sync/training/2-20260726-20261025.csv \
  .runtime/kra/sync/training/3-20260726-20261025.csv \
  --windows 3 --test-days 30 --output .runtime/kra/windows-evaluation.json
```

기존 2025 서울 이력을 추가하되 각 검증 시작일 이전의 자료만 학습합니다. 서울/서울+부산/제주를 분리하고 자료 부족은 그대로 표시합니다. 서울 단독과 통합 모델은 같은 서울 검증 기간에서 비교하며 배당이 있는 동일 경주의 `modelOnMarketSubset`과 `market`을 비교합니다. 중복 경주의 내용이 다르면 합치지 않고 중단합니다. 점수는 보정된 승률이나 수익률이 아닙니다.

클라우드에서 서울 2025 CSV로 직접 확인한 결과:

| 검증 기간(끝 날짜 제외) | 시장 비교 경주 | 모델 AUC | 시장 AUC |
|---|---:|---:|---:|
| 2025-09-30 ~ 2025-10-30 | 55 | 0.714 | 0.791 |
| 2025-10-30 ~ 2025-11-29 | 87 | 0.742 | 0.822 |
| 2025-11-29 ~ 2025-12-29 | 107 | 0.736 | 0.767 |

세 구간 모두 모델이 시장 기준선보다 낮아 서비스 모델을 교체하지 않았습니다. 사용자 PC의 2026 자료와 제주·부산을 합친 평가는 위 명령으로 별도 확인해야 합니다.
