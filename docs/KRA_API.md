# 한국마사회 경주성적 API 연결 확인

API214_1 개발계정 승인 후 사용하는 **로컬 연결 확인·원본 다운로드 도구**입니다. Python 표준 라이브러리만 사용하므로 Docker 실행, npm 설치, Python 추가 패키지가 필요하지 않습니다. API 호출은 사용자의 PC에서 이루어집니다.

원본을 다운로드한 뒤 아래의 **서울 경주 사이트 반영** 절차로 DB에 최초 등록할 수 있습니다. 기존 가상 샘플과 회원 자료를 보존하며, 실제 자료에는 한국마사회 출처를 표시합니다. 실제 데이터로 ML을 학습하지 않습니다.

## 처음 한 번 설정

WSL Ubuntu 터미널에서:

```bash
cd ~/projects/horse_racing_portal_wsl
git pull --ff-only
python3 scripts/kra.py configure
```

공공데이터포털의 **마이페이지 → 데이터 활용 → Open API → 개발계정 → 한국마사회_경주성적정보**에서 인증키를 확인합니다. 메뉴 이름은 포털 개편에 따라 다를 수 있습니다. 해당 API의 승인 여부를 확인하세요.

가능하면 **일반 인증키(Decoding)**를 복사하고, 위 명령이 입력을 기다릴 때 터미널에 붙여넣어 Enter를 누릅니다. 입력한 문자가 화면에 보이지 않는 것이 정상입니다. Encoding 키도 한 번 디코딩해서 처리합니다. URL 전체를 붙여넣지 마세요.

키는 Git에서 제외된 `.runtime/kra/service-key`에 소유자만 읽고 쓸 수 있는 권한으로 저장됩니다. 암호화 저장은 아닙니다. 채팅·스크린샷·GitHub에 키를 공유하지 마세요. 다시 `configure`를 실행하면 키를 바꿀 수 있습니다. 기존 `.env`와 Docker 설정을 수정할 필요가 없습니다.

자동화 환경에서는 `KRA_SERVICE_KEY` 환경변수를 사용할 수 있으며 이 경우 저장 파일보다 우선합니다. 명령행 인수로 키를 받지 않습니다.

## 연결 확인 (한 번 호출)

```bash
python3 scripts/kra.py check --meet 1 --date 20220220 --race 1
```

문서에 수록된 **서울 2022년 2월 20일 1경주** 조건입니다. 현재 API가 그 기간의 자료를 제공하는지는 실제 호출로 확인해야 합니다. 이 도구는 `rc_date`만 지정하며, 원본 가이드 예제의 중복 연도·월 조건을 복사하지 않습니다.

성공 예시(건수는 실제 응답에 따라 달라집니다):

```text
API 연결 성공: 전체 N건 / 수신 N건 / 호출 1회
전체 조회 완료
저장 위치: .runtime/kra/results-...
```

`check`는 첫 100건만 확인합니다. 더 많은 건수가 있으면 **첫 페이지 확인 완료**라고 표시하고 `summary.json`에 `complete: false`를 기록합니다. 0건은 인증 실패와 다릅니다. 해당 경주일·경마장·제공 기간을 확인하세요.

오류는 키나 요청 URL 없이 표시합니다. 오류 20/30은 승인 내역 및 키, 31은 사용 기간, 32는 허용 IP, 22는 호출 한도를 확인하세요. HTTP/네트워크 오류만으로 인증 실패라고 판단하지 않습니다. 실패 시 자동 반복 호출하지 않습니다.

## 해당 날짜 전체 내려받기

연결이 확인된 뒤 필요한 날짜로 바꿔 실행합니다:

```bash
python3 scripts/kra.py fetch --meet 1 --date 20220220
```

- `--meet`: 1 서울 / 2 제주 / 3 부산경남. 영천은 문서 간 버전 차이가 있어 아직 선택지에 추가하지 않았습니다.
- `--date`: YYYYMMDD 형식. 초기에는 하루만 조회하세요.
- `--race`: 특정 경주만 받을 때 추가합니다.
- 한 페이지 100건, 실행당 최대 10페이지(10회 호출), 페이지 사이 최소 0.25초 대기. 한도를 넘으면 `--race`로 범위를 줄이세요. 이 상한은 개발 도구의 자체 제한입니다.
- 각 실행은 새 디렉터리에 XML 원본 페이지와 `summary.json`을 저장합니다. 인증키가 응답에 그대로 포함돼 돌아오면 해당 문자열을 제거합니다. 오류 응답은 저장하지 않습니다.
- 전체 건수 변경·불완전 페이지·동일 말의 동일 경주 중복·조회 날짜 불일치를 감지하면 정상 완료로 처리하지 않습니다. 시점별 정정 여부와 모든 필드의 의미까지 검증하는 도구는 아닙니다.

## 서울 경주 사이트 반영

먼저 최신 코드를 받고 기존 실행 환경에서 재빌드합니다. V9가 제공기관 식별번호, 경주 당시 조교사, 코너 기록, 원본 보관 테이블을 추가합니다. 아래 폴더명은 사용자가 연결 확인에 성공한 예시이며, 본인의 실제 저장 위치를 사용하세요.

```bash
cd ~/projects/horse_racing_portal_wsl
git pull --ff-only
source .runtime/build-python/bin/activate
./scripts/up.sh
python3 scripts/kra_import.py .runtime/kra/results-yl8dg5cl
```

미리보기에서 `검증 완료: 서울 1경주 / 14두 출전`처럼 경주·출전 건수를 확인합니다. 이 단계는 DB를 변경하지 않습니다. 자료가 맞으면:

```bash
python3 scripts/kra_import.py .runtime/kra/results-yl8dg5cl --apply
```

반영된 경주의 `http://localhost:5173/races/번호` 주소가 출력됩니다. 브라우저에서 해당 주소를 여세요. 또는 **경주·결과 → 개최일 2022-02-20**으로 검색합니다. 관리자 계정·비밀번호를 입력할 필요 없이, 로컬 Docker DB에 대한 기존 권한으로 반영합니다.

중요한 기존 회원/메모 자료가 있다면 재빌드 전 `python3 scripts/backup.py`로 백업 및 별도 스키마 복원을 확인할 수 있습니다. 이 백업은 로컬 보관이며 다른 서버로의 재난 복구를 검증하지는 않습니다.

### 이번 반영 범위

- 서울의 **오늘 이전 경주, 모든 출전마가 정상 완주하고 착순·기록이 유효한 전체 경주**만 지원합니다. 경주 범위 안의 페이지가 완전히 수신되어야 합니다. API의 결과 수가 완전해도 제공기관 원본 자체가 잘못된 경우까지 자동 검증하는 것은 아닙니다.
- 같은 경주 원본은 재실행해도 중복 등록하지 않습니다. 같은 경주의 내용이 달라지면 정정 처리 절차가 필요하므로 중단합니다. 여러 경주 중 하나라도 DB 검사에서 실패하면 실행 전체를 롤백합니다.
- 기존 샘플과 이름이 같아도 제공기관 번호로 별도 식별합니다. 앞의 0을 보존합니다. 말 기본 정보와 인물 이름은 최초 등록 값을 유지하며 경주 당시 기수·조교사 이름은 각 출전 기록에 보관합니다. 모색·혈통·발주 시각·게이트가 원본에 없으면 임의로 채우지 않습니다. 서울 경주의 주로는 더트로 분류합니다.
- 거리 구간은 출발 200m, 결승 전 600m/200m, 결승을 저장합니다. 코너 기록은 별도 표로 표시하고 임의 거리로 변환하지 않습니다. 샘플 서울 기록의 마지막 600m는 75.9−36.6=39.3초입니다.
- 단승 배당은 배수로 표시하고 수집 시각을 **수집**으로 명시합니다. 제공기관이 배당을 확정한 시각이라고 주장하지 않습니다. 공식 인기 순위는 미제공으로 유지합니다.
- `plcOdds` 및 기타 원본 필드는 `kra_race_import.raw_json`에 보존합니다. 승식 설명 충돌이 해결되지 않아 연승/복승 표나 원화 환급금을 생성하지 않습니다. 실제 경주 화면에는 일본의 엔화 환급 안내를 표시하지 않습니다.
- 경주 당시 조교사 ID로 성적을 집계합니다. 해당 정보가 없는 기존 샘플/수동 자료만 현재 담당 말의 전적을 사용합니다.
- 가져온 말·인물·경주·출전·구간은 웹 관리자 양식에서 수정하지 못하게 하여 원본과 표시가 달라지는 일을 방지합니다. 정정·취소·실격·중지·새 경마장 지원은 후속 범위입니다.
- 한국마사회 실제 경주에는 합성 학습 모델의 점수를 제공하지 않습니다. 공식 주행 스타일 분류도 아니며, 1경주만 가져오면 대표 주행 스타일은 표본 부족으로 판단 보류일 수 있습니다.

## 제공 조건과 연동 시 주의점

사용자가 2026-10-23 제공한 [공공데이터포털 상세 페이지](https://www.data.go.kr/data/15063979/openapi.do) PDF에는 무료, 이용허락범위 제한 없음, 개발 자동승인/운영 심의승인, 개발 트래픽 3,000이 표시돼 있습니다. PDF에는 호출 한도의 집계 기간이 없으므로 포털 계정의 실제 한도를 확인하세요. 공개 운영 시 운영계정 조건을 확인해야 합니다.

`API214_1_한국마사회 경주성적정보.docx`와 위 PDF를 근거로 작성했습니다. 최신 PDF는 HTTPS·JSON/XML·영천을 안내하지만 가이드의 개요는 HTTP·XML·3개 경마장을 안내합니다. 이 도구는 HTTPS와 XML을 사용하고 실제 호출 성공은 별도로 검증해야 합니다.

- `hrNo`, `jkNo`, `trNo`는 선행 0을 보존하는 문자열입니다. `chulNo`는 출전번호이며 말의 고유번호와 다릅니다.
- 서울: 누적 시간. 제주: 구간 기록. 부산경남: 구간 및 누적 시간. 원본 필드를 보존하며 현재 도구는 임의로 시간을 변환하지 않습니다.
- 사용하지 않는 구간에 0이 나타납니다. 이를 실제 0초/0위로 해석하지 않습니다. 모든 필드의 0이 결측이라는 뜻은 아닙니다.
- S1F는 출발 200m, G3F/G1F는 결승 전 600m/200m입니다. 코너는 근거 없이 거리 좌표로 변환하지 않습니다.
- `winOdds`는 단승 배당입니다. `plcOdds`는 포털의 연승 설명과 DOCX의 복승 설명이 충돌하므로 의미 확인 전 승식을 확정하지 않습니다.
- 공식 인기 순위·예정 출전표·실시간 배당 추이는 이번 명세에서 확인되지 않았습니다. `rankRise`(승군순위)를 인기 순위로 사용하지 않습니다.
- 제공기관 ID, 서울 구간 자료, 경주 당시 조교사 이력은 이번 반영 도구에서 처리합니다. 금액 환급·취소/실격·정정 및 다른 경마장은 아직 처리하지 않습니다.

## 승인된 다른 API 탐색 (kra_catalog.py)

사용자 계정에 승인된 51개 API의 명세는 [KRA_API_CATALOG.md](KRA_API_CATALOG.md)에 정리했습니다. `scripts/kra_catalog.py`는 그중 사이트와 관련된 36개를 같은 인증키로 호출해 원본(XML)과 `rows.json`, `summary.json`을 `.runtime/kra/<api>-…/`에 보존하고, 첫 행의 항목과 값을 요약해 출력합니다. DB는 변경하지 않습니다.

```bash
python3 scripts/kra_catalog.py list                      # API 이름과 조건
python3 scripts/kra_catalog.py probe horse-list meet=1 --rows 5
python3 scripts/kra_catalog.py probe horse-info hr_no=039092
python3 scripts/kra_catalog.py fetch jockey-info meet=1 --pages 3
```

- 조건은 `이름=값` 형식이며 각 API가 받는 조건만 허용합니다. 필수 조건이 빠지면 호출 전에 중단합니다.
- `probe`는 1회, `fetch`는 최대 `--pages`회(기본 10, 상한 50) 호출하며 페이지 사이 0.25초 대기합니다. 개발계정의 API별 트래픽 한도를 확인하세요.
- `birthday`가 `********`로 오면 마스킹으로 표시하며 추정하지 않습니다. 인증키는 출력·저장 파일에 포함하지 않습니다.
- 검증: `python3 -m unittest discover -s tests -p 'test_kra_catalog.py' -v` (오프라인 6개).
