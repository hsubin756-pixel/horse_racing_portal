# 배포와 운영 준비
현재 Compose는 단일 Linux 개발/시연 환경용입니다. 외부 운영 서버에 실제 배포하지 않았으며 비용이나 HTTPS 설정 완료를 주장하지 않습니다.

- 서버: Docker/Compose를 지원하는 Linux VM, 초기 권장 2~4 vCPU/4GB 이상 RAM/20GB 이상 디스크. 실제 용량은 데이터/트래픽에 따라 측정하세요. 클라우드 VM·디스크·백업·도메인·트래픽 비용이 발생합니다. 요금은 공급자와 리전에 따라 다르므로 배포 시 견적을 확인합니다.
- 외부 공개는 reverse proxy(Caddy/Nginx 등)의 HTTPS 443으로만 하고 프론트 포트로 전달합니다. DB/API/ML 직접 외부 공개를 피합니다. 현재 loopback 바인딩을 무분별하게 0.0.0.0으로 바꾸지 않습니다.
- 운영 JWT_SECRET은 암호학적으로 안전한 최소 32바이트 키, DB 비밀번호는 운영 비밀 관리 도구에서 주입합니다. `.env` 예시의 빈 문자열을 그대로 사용하지 않습니다. 토큰 키 교체 시 기존 세션은 무효화됩니다. proxy placeholder 기반 비밀값은 로컬 DB/암호 연산용 원시 키를 대체할 수 없습니다.
- MySQL 볼륨은 `keiba_mysql_data`이며 VM 디스크/볼륨의 보존 및 암호화를 설정합니다. 정기적인 mysqldump 또는 스토리지 백업과 실제 복구 테스트가 필요합니다. 환경 스냅샷이 Docker named volume을 보존한다고 가정하지 않습니다.
- Flyway는 시작 시 순서대로 migration을 적용합니다. 적용된 migration을 수정하지 말고 새 버전을 추가하세요. 운영 변경 전 백업을 준비합니다.
- 실제 서비스에서는 가입/로그인 rate limit, 이메일 인증/복구, 관측성/경보, 비밀 회전, 토큰 철회 테이블 만료 레코드 정리를 추가 검토합니다. 현재 SRS 범위에는 포함되지 않습니다.
- 이미지 태그를 배포 시 digest로 고정하고 취약점 검사/정기 업그레이드 정책을 운영하세요. 테스트된 프로젝트 의존성은 Gradle 및 npm/Python lockfile에서 확인합니다.
- 브라우저 CSP 및 nosniff 헤더를 Nginx에서 제공하며 API CORS는 같은 출처 프록시 흐름을 전제로 합니다. JWT는 Bearer 헤더에만 사용하고 쿠키 세션을 사용하지 않아 이 API에는 CSRF를 비활성화했습니다. HTTPS는 배포 reverse proxy에서 종단합니다.
- 새 클라우드 task의 컨테이너/볼륨 복구는 별도로 검증해야 합니다. 코드만 있는 새 머신에서는 `scripts/up.sh`로 이미지와 가상 샘플 DB를 재구축할 수 있습니다. 회원/즐겨찾기 보존은 별도 DB 백업 복원이 필요합니다.
